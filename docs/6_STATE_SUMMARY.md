# 6. State Summary (Rolling Memory)

- **Prompt 1 (Architecture):** Scaffolded the StockSync inventory platform docs (PRD, architecture, schemas, 23-task graph) and `.env.example`. Stack: Node 22/TS, Express 5, PostgreSQL, React/Vite PWA, Meta + Telegram messaging, deployed on Azure Container Apps.
- **T01:** Set up npm workspaces with strict TypeScript 6, ESLint (no-explicit-any enforced) and Vitest. Added a zod-validated env loader that rejects weak JWT secrets and bad DB URLs.
- **T02:** Added a pg pool factory with TLS for Azure PostgreSQL, a withTx helper, and an advisory-locked idempotent SQL migrator. The 001_init.sql schema implements every table from 3_SCHEMAS.md, and tests run against real Postgres.
- **T03:** Added createApp with helmet CSP, CORS allowlist, rate limiting, raw-body capture for webhook signatures, and /healthz. A central error handler maps domain, zod and Postgres errors to safe JSON responses without leaking internals.
- **T04:** Added bcrypt + HS256 JWT login with timing-safe unknown-email handling, per-request user revalidation (deleted users lose access), and a viewer<staff<admin RBAC middleware. Admins manage users via /api/users, and a bootstrap admin is created from env on first start.
- **T05:** Added a generic SimpleRepo + crudRoutes factory (whitelisted columns, escaped ILIKE search) and a ProductsRepo that computes totalQuantity across warehouses. Products support normalised SKUs, JSON custom attributes, search/category/low-stock filters, and duplicate-SKU 409s.
- **T06:** Added warehouse CRUD on the generic crud router with uppercase unique location codes. Stock is tracked per product per warehouse from here on.
- **T07:** Added StockService with receive/issue/adjust/transfer. All writes go through one conditional UPDATE (never below zero) plus an immutable ledger row, with row locks taken in a consistent order to avoid deadlocks. A 25-way race test proves no overselling, and post-commit observers enable realtime and alerts.
- **T08:** Added supplier and customer CRUD with email/phone validation. CustomersRepo.findOrCreateByChannel idempotently maps a chat identity (e.g. a WhatsApp number) to a customer record.
- **T09:** Added SettingsService (JSONB key/value merged over defaults) for business name, currency, WhatsApp number, default warehouse, alert recipients and custom field definitions. Admins change them via PUT /api/settings without redeploying.
- **T10:** Added an in-process EventBus and an authenticated /api/events Server-Sent Events stream with heartbeats and a connection cap. Stock changes now publish stock.changed events carrying the new warehouse and total quantities.
- **T11:** Added OrdersService: create (price snapshot, merged lines), confirm (all-or-nothing stock deduction from the chosen or default warehouse), fulfill, and cancel (restocks confirmed orders). Every transition publishes realtime events and calls status observers, which customer notifications will use.
